# リアルタイム共同編集(0.6.0)

同じ構成ラフを複数人が同時に編集し、互いの居場所・選択・カーソル・変更が 1 秒以内に見えるようにした。
中継は gg-manager の Hocuspocus。`io.collab` を渡した利用側だけで動き、渡さなければ 1 バイトも挙動は変わらない。

## 全体の形

```
エディタ(タブ) ──┐
                  ├─ WebSocket 1 本 ─→ Hocuspocus ─→ 書き戻し役(dev サーバー)─→ ページファイル
エディタ(別の人)─┘        ↑ 部屋を相乗り
```

- **部屋は 2 つ**。案件の部屋(`wf/<乱数>__@project`)に居場所と各ページの版(`Y.Map("pages")` の `rev`)、
  ページの部屋(`wf/<乱数>__<route>`)に本文(`Y.Text("html")`)と選択・カーソル
- 1 タブの WebSocket は 1 本(`HocuspocusProviderWebsocket`)。部屋はそこへ `attach()` で相乗りさせる
  (v3 は `websocketProvider` を共有すると `attach()` を呼ぶまで繋がらない)
- ページを移ると部屋を付け替える。前の部屋は 4 秒の猶予のあとに抜ける(行って戻る操作で繋ぎ直さないため)。
  WebSocket も最後の部屋が抜けてから 5 秒後に閉じる
- 中継は**認証も保存もしない**。部屋名に入れた乱数が鍵で、全員が抜けると中身は消える(ファイルに残すのは書き戻し役の仕事)

`useCollab` が `import('./runtime')` で動的に読む。`io.collab` を渡していない利用側のバンドルでは、
この塊は別チャンクのまま読み込まれない。

## 本文の同期

### 種まき

部屋が同期して `html.length === 0` なら、**エディタが**読み込み直後の姿を 1 回だけ入れる。
一時の `Y.Doc` の `clientID` を本文の FNV-1a 32 にして `insert` するので、同じ本文なら
何人が同時に撒いても構造体の ID が同じになり、Yjs が重複を捨てる(2 人同時に開いても本文が二重にならないことを検証した)。

撒くのは **`EditorCanvas` の初期化(`initLayout`)が終わってから**。ここは絶対配置への変換・
書き戻し用の指紋(`data-gg-base`)・`data-element-id` の付与が済んだ時点で、`getCleanHtml` の結果が安定する。
初期化の途中で撒くと人によって本文が食い違う。合図は `gg:editor-document-ready` イベント(`collab/signals.ts`)。

### 自分の変更 → Y.Text

- きっかけは 2 つ。履歴の `present` が変わったとき(`notifyIframeChange` 経由の編集)と、紙面の `input`(打鍵)
- 120ms 間引いて `encode(getCleanHtml(doc))` を作り、**shadow**(最後に Y.Text と揃えた姿)との差分を送る。同じなら送らない
- 送るのは 1 つの transaction。origin はそのタブの束縛オブジェクトなので、自分の変更で当て込みは起きない

### 他人の変更 → 紙面

`html.observe` で自分以外の origin の変化を拾い、16ms まとめてから idiomorph で `#artboard` に当てる。

- エディタ専用の属性(`contenteditable` `data-editable` `data-element-id` `data-original-*` `data-gg-base` …)は消させない
- 一時クラス(`selected` `editing` …)は当てたあとに付け直す。表示専用のノード(選択枠・コメント層・共同編集の層)は
  一度外して当て、終わってから元の位置へ戻す
- **打鍵中の要素(`[contenteditable="true"]`)には触らない**。そこに掛かる変更があれば「反映待ち」を出し、blur で当て直す
- ポインタを押している間(ドラッグ・リサイズ)は当てず、離してから当てる
- 当てたあとは履歴の `setHtml`(段を作らない)で `present` を追従させる。
  当て込みで動く MutationObserver は `data-editable` を足すだけで、`getCleanHtml` の結果は変わらないので送り返さない

### 自分と他人が同時に直したとき(merge.ts)

紙面と Y.Text は 1 文字も違わないとは限らない(打鍵中の保留、当て込み後の属性の並びなど)。
そこで shadow を軸にして、
`shadow → 今の紙面`(自分)の差分を `shadow → Y.Text`(他人)に通し、Y.Text の位置へ写してから当てる。
自分の削除は他人が既に置き換えた範囲を消さない。離れた節の同時編集は両方残る(乱数 3000 通りで確認)。

### 取り消し

共同編集中の ⌘Z / ⇧⌘Z は `Y.UndoManager`(`trackedOrigins` = そのタブ、`captureTimeout` 500ms)。
自分の変更だけが戻り、他人の変更は残る。結果は他人の変更と同じ経路で紙面に当たる。
ショートカット・ツールバー・リボンの 3 つの入口はすべて同じ関数を通す(接続していなければ従来の履歴)。

## 居場所(awareness)

- ページの部屋: `{ user, kind: "editor", selection, cursor, editing }`。
  `selection` / `editing` は `anchorValueOf`(`PptComments.tsx`)の値 ── `data-element-id` は読み込みのたびに変わるので使えない。
  `cursor` は紙面(`#artboard`)の px で、50ms 間引いて送る
- 案件の部屋: `{ user, kind: "editor", contentId, route }`。書き戻し役は `kind: "bridge"` で入るので、数だけ数えて「書き戻し先 n」を出す
- 同じ人が複数のタブで開いていてもアバターは 1 つ(`user.id` でまとめる)。色は `user.id` の hash から 8 色

## 保存との関係

- ページの部屋に入っている間、`onSave` の自動保存は呼ばない。手動保存も「同期済み」を出すだけ
- 代わりに未同期(`provider.unsyncedChanges > 0` かオフライン)があれば `beforeunload` で警告し、
  `pagehide` / `visibilitychange` で送り残しを出す
- ヘッダーの保存状態は接続中だけ「同期済み / 同期中 / オフライン / 反映待ち」に変わる
- 本文を送ったら案件の部屋の `pages[route].rev` を進める(1 秒に 1 回まで)。
  他の人の rev を見たエディタは、そのページの部屋の本文で**見るだけの紙面**を描き直す。
  部屋に本文が無ければ 2 秒待ってからファイル(`io.loadContent`)で読み直す(書き戻しの 1.5 秒を跨ぐため)
- 共同編集中のページ切替は、部屋に本文があればファイルより優先して開く(書き戻し前でも最新の姿になる)

## 確かめたこと

中継はローカルの Hocuspocus(`scratch/collab/hp-local-a`、127.0.0.1:5418)、
利用側は playground(5410、`?collab=ws://127.0.0.1:5418&name=A&room=…`)。
`scratch/collab/verify-collab.mjs`(Playwright、browser context 2 つ)で **1 ページ表示 17 / キャンバス 21 / collab 無し 6**。

- 参加者が互いに見える・接続状態・書き戻し先の数・ページの色の点
- 相手の選択枠(名前札)とカーソルが紙面に出る
- 文字の編集が相手に届くまで **172〜219ms**(1 秒以内)
- 別の節を同時に直すと両方残る / 同時に開いても種まきで本文が二重にならない
- ⌘Z で自分の変更だけ戻り、相手の変更は残る。⇧⌘Z で戻る
- 相手が打鍵中は反映が保留され(「反映待ち」表示)、blur で入る。打鍵した文字は相手にも届く
- 片方をオフラインにして両者が別々に編集 → 復帰で両方の変更が揃う
- 保存 HTML(`getCleanHtml`)に `.gg-collab-layer` が入らない / 接続中は `onSave` が 0 回(手動保存でも 0 回)
- `collab` を渡していない利用側では共同編集の UI が出ず、WebSocket も張らず、自動保存が今までどおり動く

`scratch/collab/probe-bridge.mjs`(8/8)で、書き戻し役の数とフレーム名の印を別に見た。
Node から `kind: "bridge"` で案件の部屋に入ると「書き戻し先 1」になり、抜けると警告に戻る(アバターには出ない)。
共同編集中は編集しても未保存の点が立たず、単独では今までどおり立つ。

記憶が使えない文脈は `scratch/collab/verify-opaque.mjs`(10/10)。
`localStorage` が例外を投げる文脈でもエディタの起動・共同編集・本文の同期が通る。

既存の回帰(0.6.0 の tgz を入れた scratch のホスト): `verify-single.mjs` 30、`verify-canvas.mjs all` 44、`verify-comments.mjs all` 40 が全部 PASS。
`tsc --noEmit` と `npm run check:version` も通る。

本番の中継(`wss://hocuspocus-server-461388837167.asia-northeast1.run.app`)へは最後に 1 回だけ疎通した
(部屋 `wf/test-<乱数>__%2F`)。2 人が同期済みになり、互いのアバターが見え、編集が 200ms で届いた。

## やっていないこと・分かっている穴

- **`CSP: sandbox` に `allow-same-origin` が無い配信ではエディタが動かない**。opaque origin のページは
  自分が作った iframe の `contentDocument` を読めない(srcdoc でも blob でも `null`、`contentWindow.document` は SecurityError)。
  共有ドロップに静的なエディタを置くなら、別オリジンで配って `allow-same-origin` を足す必要がある(実測済み。パッケージ側では回避できない)
- 要素単位の CRDT(`Y.XmlFragment`)にはしていない。本文は HTML 文字列の CRDT で、同じ場所を同時に直すと文字が混ざる
- 認証(部屋名が鍵)。コメントは今までどおり dev サーバーのファイルで、共同編集には載せていない
- 見るだけの紙面の中に他人のカーソルは出さない
- 書き戻し役(dev サーバー側)はこのパッケージの担当外(html-starter の `vite-plugin-wf`)
- 共同編集中は「未保存」の印(フレーム名の点)を出していない(`isDirtyForCanvas` に `!collabPageActive`)
  ── 保存の概念が書き戻し役へ移り、印が立ちっぱなしになるため。代わりに接続状態を出している
- 他人の変更を当てた紙面には、その人が付けた書き戻しの印(`data-gg-dirty`)がそのまま残る。
  単独の保存では写しから毎回作り直す印なので、そこだけ挙動が違う
  (構成ラフの HTML 正本では無害。TSX への書き戻しでは、自分が触っていない要素も書き戻しの対象になりうる)
- スライドの一覧(`PagesPanel`)の色の点は、キャンバスが無いときページ番号(`String(n)`)を id と見なす。
  id が番号でない利用側では、一覧に点が出ない(キャンバスのフレーム名には出る。落ちはしない)
