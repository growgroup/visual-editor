# 自由配置(0.5.0)

構成ラフ(`editorMode: 'webpage'`)で、**器ごとに「流し込み」と「絶対配置」を切り替えられる**ようにした。
Figma の「絶対位置」トグルと同じ考え方で、既定は今までどおり流し込みのまま。切り替えた範囲の中だけが自由に動く。

## なぜ必要だったか

構成ラフは版面を流し込み(フロー)のまま保つ約束で作ってある(README「editorMode で挙動が変わる」)。
倒すと版面が固定 px に固まり、別の幅で崩れ、次工程の入力として意味を失うためだった。
その代わり **「この帯の中だけ自由に置きたい」ができなかった** ——ドラッグは同じ親の中の並べ替えだけ、
矢印キーは並び順を 1 段動かすだけ、右パネルの X / Y は「絶対配置ではないため指定できません」。

範囲を器で区切れば、流し込みの利点(ページ高さが崩れない・幅が変わっても追従する)を保ったまま自由配置を混ぜられる。
提案書(`slide`)の「開いた瞬間に全部倒す」とはまったく別の仕組みで、**ユーザーが指示した範囲だけ**を倒す。

## 使い方

| したいこと | 操作 |
| --- | --- |
| この帯の中だけ自由に置く | 器(セクションなど)を右クリック → **子をすべて絶対配置にする** |
| 流し込みへ戻す | 同じ器を右クリック → **流し込みに戻す** |
| この要素だけ流れから外す | 右パネル「位置」→ **配置: 自動 / 絶対** |
| ページ全体を自由配置にする | 右クリック → **このページを自由配置にする…**(確認あり) |
| ページ全体を戻す | 右クリック → **ページを流し込みに戻す…**(確認あり) |

- 自由配置の器を選ぶと、選択枠の右上に **自由配置** の札が出る(部品の札は左上なのでぶつからない)
- 器の中の子は、ドラッグ・矢印キー・右パネルの X / Y で自由に動く。**器の外へは出ない**
- 流し込みのままの要素は今までどおり並べ替え。X / Y は触れない(効かない入力を無くした)
- `slide` の挙動は 1 つも変えていない。自由配置の UI は `webpage` にしか出ない

## 目印(保存 HTML に残るもの)

`data-gg-*` は保存時のサニタイズで落ちるので、正本まで届く印は **class** にするしかない(`restore-flow.ts` の注記と同じ理由)。

| class | 意味 |
| --- | --- |
| `gg-freelayout` | この器は「子をすべて絶対配置」にしてある。インラインの `height` はこの変換が書いたもの |
| `gg-freelayout-rel` | この変換が `position: relative` を足した(元は `static`)。解除でインラインの `position` を外してよい合図 |
| `gg-freelayout-hold` | 器ではないが、子を 1 つ以上フローから抜いたので高さを固定した。抜いた子が全部戻ったら高さも外す |

保存 HTML はこうなる:

```html
<section class="wf-gutter py-16 gg-freelayout-rel gg-freelayout" style="position: relative; height: 353.547px">
  <div style="position: absolute; left: 130px; top: 72px; width: 764px; height: 25.6px; margin: 0; flex: none; ...">…</div>
  …
</section>
```

印を 3 つに分けたのは、**読み直したあとでも解除が決定的に効く**ようにするため。
`data-gg-prestyle`(変換前 style の退避)は保存時に剥がされるので、解除の判断材料にはできない
——同一セッション中の「元の値の書き戻し」にだけ使う。解除そのものは、退避が無くても
`position / left / top / right / bottom / width / height / margin / flex / flex-grow / flex-shrink`
を無条件に外して成立させている。

## 判断したこと

### 寸法は `getComputedStyle` の値をそのまま書き戻す

最初は既存の一括変換(`dom-utils.ts`)にならって `Math.ceil(rect.width / ズーム倍率)` を使ったが、
変換の前後でスクリーンショットを比べると **枠線が半画素ずれる**(カード 3 枚の下辺で 3 行ぶんの差)。
`offsetWidth` / `offsetHeight` は整数に丸められるので、214.4px の帯を 214px で固定すると版面が 0.4px 詰まり、
下にあるものが全部わずかにずれる。

実測で確かめたところ、`getComputedStyle().width / height` は **その要素の `box-sizing` と同じ物差し**で、
端数まで含めた使用値を返す:

| box-sizing | `style.height: 100px` のとき computed | offsetHeight |
| --- | --- | --- |
| `border-box` | `100px`(= border box) | 100 |
| `content-box` | `100px`(= content box) | 124(padding 10×2 + border 2×2) |

つまり `style` へそのまま書き戻せば、`box-sizing` が何であれ寸法は 1px も動かない。
この方式に変えて、変換前後の画素差は **0.000%** になった(器の変換・ページ一括ともに)。

### 採寸と書き込みを分ける

1 要素ずつ「測って書く」を繰り返すと、先に倒した要素が流れから抜け、その分だけ後続の兄弟が上へ詰まってから測られる。
`convertToAbsolutePositioning` と同じく **全部測りきってから全部書く**。
位置は `offsetLeft / offsetTop`(CSS px で、ズームの transform の影響を受けない)を使い、
`offsetParent` が器になっていない要素(SVG など)だけ矩形から割り戻す。

### 変換で 1 つでもずれたら、変換ごと巻き戻す

採寸のタイミング(画像・書体の遅延適用)が悪いと間違った座標で固定されて版面が崩れる。
`dom-utils` と同じ方針で、変換後に全部の矩形を測り直し、1.5px 以上ずれた要素があれば
器と子の style / class を丸ごと元に戻して `0` を返す(呼び出し側はトーストで知らせる)。
崩れた編集画面より、変換されていない編集画面のほうがはるかにまし。

### 器の高さを固定する

子が絶対配置になると流れから抜け、器の auto 高さが 0 に潰れる——「セクションが消えた」に見える一番の事故。
倒す**前に**今の高さを固定する。ページ一括の確認ダイアログに
「セクションの高さが固定され、内容を足しても下に押し出されなくなります」と書いているのはこのため。

要素 1 つだけを絶対にする場合も同じ問題が起きる(`#artboard` 直下のセクションを抜くと後続が詰め上がる)ので、
親が `gg-freelayout` でなければ親の高さを固定して `gg-freelayout-hold` を残す。
「自動」へ戻したとき、その親にフロー外の子が 1 つも残っていなければ高さの固定も外す。

### ページ一括の対象は `main` を探して決める

仕様は「`#artboard` の直下の子、`main` があればその直下」。ただし構成ラフの殻は
`#artboard > .wf-frame > .flex > .flex-1 > main` のように何段も挟み、隣に注釈の欄(`aside`)が並ぶ。
`main` を直下に限ると注釈の欄ごと倒してしまうので、`artboard.querySelector('main')` で探す。
`main` が無いページだけ `#artboard` の直下に落とす。

artboard 自身は倒さない——倒すとセクションが重なり、ページの高さが 0 になる。
セクションは流し込みのまま積み、**それぞれの中だけ**を自由配置にする。だからページ高さは変わらない(実測 3910 → 3910)。

### 解除は「今見えている位置の順」に並べ直す

`restore-flow.ts` の「ONにした瞬間」と同じ考え方。並べ替えの順を**先に決めてから** position を外す
——先に外すと要素が積み上がって動いてしまい、「見えていた順」が分からなくなる。
上から下、同じ段なら左から右(行優先)。段の判定には 4px の遊びを持たせた。1px の誤差で段が割れると、
横並びのカードが縦にばらけて戻ってしまう。

### 「レイアウト」トグルとは統合しない

右パネルの「レイアウト」(`gg-autolayout`)は **slide の flex の器**の意味で作ってあり、
`flex-reorder.ts` の `shouldReorder` が slide 専用の入口として読んでいる。
同じスイッチに 2 つの意味を持たせると、どちらの世界の話をしているのか分からなくなる。別の操作として足した。

### 「位置」セクションを webpage でも開くようにした

以前は `position: editorMode !== "webpage"` で、流し込みのページでは畳んでいた(X / Y が効かず詳細操作だったため)。
自由配置の「配置: 自動 / 絶対」がこの中に入り、流し込みを抜ける入口になったので、畳んだままだと見つけられない。

## 操作の追従

| 操作 | 絶対配置の要素 | 流し込みの要素 |
| --- | --- | --- |
| ドラッグ | 座標で自由移動(器の外へは出ない) | 同じ親の中の並べ替え(従来どおり) |
| 矢印キー | 座標移動 | 並び順を 1 段動かす(従来どおり) |
| リサイズ | 位置ごと変わる | 幅・高さだけ(従来どおり) |
| 右パネル X / Y | 編集できる | 触れない(理由をツールチップに出す) |

保存 HTML で位置がいつも inline style とは限らない。既存の Tailwind 変換(`convertInlineStylesToTailwind`)が
ドラッグを離した瞬間に `left: 0px` を `left-0` クラスへ畳むため、きりのいい値はクラスで表される。
見た目も解除の結果も変わらない(解除は inline を外し、`gg-freelayout` を外すだけで流し込みへ戻る)。

ドラッグと矢印キーは **既に通っていた道をそのまま使っている**。
`resolveWebpageDrag` は「全部フロー外なら `free`(従来どおりの自由移動)」を返すし、
`reorderSelectionByStep` は `free` のとき `null` を返して座標移動へ落ちる。
足したのは「器の外へ出さない」だけ(`computeFreeBounds`)。
群で掴んだときは各要素の許容範囲の**共通部分**を使う——要素ごとに丸めると、端に着いた要素だけ止まって隊列がばらける。

## 検証

playground(`5399`)と構成ラフの実物(`wf-free` / `5397`)を Playwright で。

| | 結果 |
| --- | --- |
| (a) 器の変換で見た目が変わらない | 子の矩形のずれ **0px** / 画素差 **0.000%** / ページ高さ 1363 → 1363 |
| (b) 子をドラッグ・矢印キー・X 入力で動かせる | 自由移動(DOM 順は不変)・矢印キーで座標が動く・X に 250 を入れて 250px へ |
| (c) 流し込みに戻す | 印と高さ固定が外れ、子の位置指定が消え、画素差 **0.000%** |
| (d) 保存して読み直しても残る | `index.html` に `gg-freelayout` と `position: absolute` が書かれ、読み直しても絶対配置のまま。**読み直し後の解除も効く**(退避が無い状態) |
| (e) ページ一括の変換と解除 | 3 セクションを変換してページ高さ・画素とも不変、解除で器が 0 に戻る |
| (f) slide の既存挙動 | 開いた時点の一括変換・選択・自由ドラッグ・矢印キー・リサイズ すべて従来どおり。自由配置の UI は出ない |
| (g) 札・リサイズ・器の外へ出さない | 札は選択枠の右上に出て部品の札(左上)とぶつからない / 器の中の子をハンドルでリサイズできる / 左上へ引くと `offsetLeft=0`、右下へ引くと `992/992`・`64/64` で止まる |

既存の回帰(`verify-single.mjs` を 5397 / 5399 向けに複製したもの)も 9/9 PASS。
typecheck(`tsc --noEmit`)も通る。

## 確かめていないこと

- **部品(`data-part`)の中の要素を器にした場合**。`parts.ts` の作りからは、インスタンスの HTML に
  インライン style と class が入るだけで定義には持ち込まれない(定義を作るときに `position/left/top` を落とし、
  `data-gg-*` を剥がす)はずだが、実際に部品の中を変換して `parts:sync` を回すところまでは試していない
- マルチフレームのキャンバス表示(`wf-editor:layout = 'canvas'`)での自由配置。1 ページ表示でしか確かめていない
- `box-sizing: content-box` の要素を器にしたとき。実測は `border-box`(Tailwind の preflight)ばかりで、
  content-box の経路はコードで分岐を用意しただけ
- 器の中で要素を**追加・削除**したあとの高さ。固定したままなので、足した分は下に押し出されない(仕様どおりだが、実案件での使い勝手は未確認)

## 気づいたこと(この変更とは別)

編集のあと **自動保存が走ると選択が外れる**。`saveIfDirty` → `setOriginalHtml` →
`FrontendVisualEditor` の `useEffect(..., [originalHtml])` が `setSelectedElement(null)` するため。
既存の操作(「前面へ」)でも同じで、この変更で入ったものではない(対照実験で確認)。
自由配置の変換直後に右クリックすると、2 秒ほど経っていた場合にメニューが「選択なし」の並びになるのはこれが理由。
直すなら `[originalHtml]` の効果を「ページが切り替わったとき」に絞る必要がある。
