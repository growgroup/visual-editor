# Alt(⌥)+ クリックでリンク先へ移る

## 2026-09-17: ⌘ / Ctrl + クリックから Alt(Mac は ⌥ Option)+ クリックに変えた

利用者の報告: ⌘ / Ctrl を押しながらリンクをクリックすると該当のページに移るが、複数選択とぶつかる。

⌘ / Ctrl + クリックは、レイヤーパネルでは「選択に足す・外す」(`EditorLayerPanel` の `handleNodeClick`)、
紙面では「最深要素を選ぶ」、⌘ + Shift + クリックは「最深要素を複数選択に足す・外す」。
⌘ を押して要素を選び足しているつもりでリンクの上を押すと、ページが移ってしまう。

紙面のクリックで空いている修飾キーは Alt だけだった:

| キー | 紙面での既存の意味 | クリックとぶつかるか |
|---|---|---|
| Shift | 複数選択に足す・外す / 軸を固定したドラッグ | ぶつかる |
| ⌘ / Ctrl | 最深要素を選ぶ / 自由配置のドラッグ / ダブルクリックでテキスト編集 | ぶつかる(今回の報告) |
| Alt | ホバーの距離メジャー(`useAltMeasure`、mousemove だけ)・中心からのリサイズ(ハンドルのドラッグ)・ズームツールの縮小(ツールを選んでいる間)・数値欄の 0.1 刻み(紙面の外) | ズームツールの間だけ。そこでは移らないようにした |

`useElementSelection` の mousedown は Alt を見ないので、Alt + クリックは素のクリックと同じ選択が起きてから移る
(0.7.0 の ⌘ + クリックが「最深要素の選択 → 移る」だったのと同じ形)。

### 変えたこと

- 移る条件: Alt だけを押してクリック。⌘ / Ctrl / Shift と一緒なら移らない
  - ⌘ / Ctrl + クリック: 最深要素を選ぶだけ(0.7.0 より前の意味に戻った)
  - ⌘ + Shift + クリック: 最深要素を複数選択に足す・外す(変わらない)
  - ⌘ + Alt + クリック: 最深要素を選ぶだけで移らない(0.7.0 と同じ)
  - Alt + ドラッグ(移動)・Alt + ダブルクリック(潜る・テキスト編集)では移らない。ダブルクリックの取り消しは 350ms の待ちのまま
- 案内とカーソル: Alt を押してリンクの上にいる間。案内は `⌥ クリックで移動: 02 サービス` / `⌥ クリックで新しいタブ: example.com`
  (Mac 以外は `Alt + クリックで…`)。Alt を押したまま ⌘ / Ctrl / Shift を足すと消え、離すと戻る
- ズームツール(`body.zoom-tool`。Alt + クリックが縮小)では移らない(`BLOCKING_BODY_CLASSES` に足した)
- Alt + クリックのリンクの既定の動作は、Chromium ではダウンロード(下の対照で実測)。紙面のリンクの click は
  `useElementSelection` の `handleClick` が `preventDefault` するが、トリミング中(`gg-cropping`)は止めない。
  そこで、Alt を押したリンクの click は `link-navigation.ts` の click(capture)でも必ず `preventDefault` する(移らないときも)
- フッターのショートカット一覧に「リンク先へ移動 ⌥クリック(Windows は Alt+クリック)」を足した
- README・`docs/multi-frame-canvas-2026-09.md`・コメントの ⌘ クリックの記述を直した

### 確かめたこと

esbuild で `link-navigation.ts` を束ね、headless Chrome(playwright-core、Mac の実行環境)で、iframe の紙面に
`attachLinkNavigation` を付けて、実際のキー操作とマウス操作(CDP の入力)で確かめた。紙面には `useElementSelection` の
mousedown(選択して `preventDefault` / `stopPropagation`)と `handleClick`(bubble、トリミング中は止めない)の代わりを付けた。
`navigate` は呼ばれたかを記録するだけで、エディタのページの切り替えは通していない。

- 32 / 32
  - 案内: Alt でリンクの上に `⌥ クリックで移動: 02 サービス` と `data-gg-link-nav`。動かしても出たまま、Shift / ⌘ を足すと消え、Shift を離すと戻り、
    Alt を離すと消える。⌘ だけでは出ない。外部リンクは `⌥ クリックで新しいタブ: example.com`
  - 移る: Alt + クリックでページへ(200ms の時点ではまだ呼ばれず、500ms で 1 回)、リンクの中の要素の Alt + クリック、外部、アンカー `#sec`
  - 移らない: ⌘ + クリック、⌘ + Shift、Ctrl、素のクリック、Shift、Alt + Shift、⌘ + Alt、Alt + ダブルクリック、Alt + ドラッグ、
    リンク以外、テキスト編集中のリンクの中、ズームツール、トリミング中
  - ダウンロード: エディタ側の `preventDefault` がある紙面・無い紙面・トリミング中・⌘ + Alt(移らない)のどれでも、Alt + クリックでダウンロードが始まらない
  - Windows の見かけ(`navigator.platform` = Win32): `Alt + クリックで移動: 02 サービス`、Alt + クリックで移る、Ctrl + クリックでは移らない
- 対照: 同じ検証を変更前(origin/main)の `link-navigation.ts` で回すと 15 / 28 で、「⌘ + クリックでは移らない」が落ちた(移った)。
  また、エディタ側の `preventDefault` が無い紙面では、変更前のコードでも、link-navigation.ts に `preventDefault` を足す前のこの変更でも、
  Alt + クリックで `download.html` のダウンロードが始まった
- `npx tsc --noEmit` が通る

### 分かっている穴(この変更で増えたもの)

- エディタに組み込んだ状態(構成ラフの殻・デッキの殻に tgz を入れる)では確かめていない。ページの切り替え・アンカーへの寄せ・新しいタブは
  0.7.0 の検証の経路のままで、この変更は触っていない
- 要素を選んでいるとき、Alt を押してリンクの上にいると、距離メジャーの赤い線と移動の案内が同時に出る
- ズームツールで止めるのは 1 ページ表示だけ。キャンバス表示では `useCanvasControls` が `body.zoom-tool` を付けない(`isInMultiPageMode` で抜ける)ので、
  キャンバス表示でズームツールを選んだまま紙面のリンクを Alt + クリックしたときの動きは確かめていない
- AltGr のある配列(欧州など)の右 Alt は Ctrl + Alt として届くので、右 Alt では移らない(左 Alt は移る)
- Windows・Linux の実機では確かめていない。Windows の Firefox は Alt を単独で離すとメニューバーが出る。
  Linux のデスクトップ環境によっては Alt + マウスのボタンをウィンドウの操作に使い、紙面に届かない

## 0.7.0: ⌘ / Ctrl + クリックでリンク先へ移る

紙面の中のリンク(`<a href>`、またはリンクの中の要素)を ⌘ + クリック(Windows などは Ctrl + クリック)すると、
リンク先へ移る。普通のクリックは今までどおり選択。

- 実装: `src/editor/utils/link-navigation.ts`(リンク先の解決と紙面のイベント)、
  `src/editor/hooks/useLinkNavigation.ts`(エディタ側の行き先)、`EditorCanvas` が紙面の読み込みごとに付ける

### 行き先

| リンク | 動き |
|---|---|
| 同じサイトのページ(`contentList[].href` と一致) | キャンバス: `focusPage` で視点を寄せ、`activatePage` で編集中にする。1 ページ表示: `onContentChange`(= `handleContentChange`)。どちらも未保存の変更を保存してから移る |
| 同じページのアンカー `#id` | その要素が見える位置へ紙面を移す。`#` だけ・`#top`(同じ id が無いとき)は先頭 |
| 別ページのアンカー `/company#access` | そのページへ移り、読み込みが落ち着いたら(500ms)その要素へ寄せる |
| 別のオリジンの http(s) | 新しいタブ(`noopener,noreferrer`)。紙面の iframe は sandbox に `allow-popups` が無いので、親のウィンドウで開く |
| `mailto:` / `tel:` / `javascript:` など | 何もしない |
| 同じオリジンで一覧に無い | 「このリンク先はページ一覧にありません」を押した所の近くに 2.4 秒出す |

ページの照らし合わせ:

- `/company`・`/company/`・`/company/index.html` は同じ。`?query` は見ない。`#hash` は上のとおりアンカーに使う
- 相対パスはページの URL を基準に解く。`/company` の中身は `company/index.html` なので、基準は `/company/`
  (`./access` → `/company/access`、`../` → `/`)。`/about.html` のように拡張子のある URL はそのまま基準
- 完全に一致するページが無いときだけ、`/about` と `/about.html` を同じと見なす
- `contentList[].href` が絶対 URL(本番のドメインなど)なら、そのオリジンのリンクも一致する
- 提案書デッキのように `href` を渡していない一覧では、サイト内のリンクは「ページ一覧にありません」。外部とアンカーは効く

### ⌘ を押している間

リンクの上ではカーソルが指になり、カーソルの右下に行き先が出る(`⌘ クリックで移動: 02 サービス` /
`⌘ クリックで新しいタブ: example.com` / 一覧に無いときは `このリンク先はページ一覧にありません` で、カーソルは変えない)。
`mailto:` などとリンク以外では出さない。紙面の外へ出る(`mouseleave` / `relatedTarget` の無い `mouseout`)・ウィンドウが
フォーカスを失う・⌘ を離すと消す。案内は親の文書に置く(キャンバスの外側の倍率で文字が縮まないように)。
カーソルは紙面の `<html data-gg-link-nav>` と `EDITOR_IFRAME_STYLES` の `cursor: pointer !important`
(選択枠などのオーバーレイの上でも指になる)。

### 既存の ⌘ / Ctrl クリックとの両立

既存の意味(`useElementSelection` / `useDragResize`):

| 操作 | 意味 |
|---|---|
| ⌘ / Ctrl + クリック | 階層を無視して最深要素を選ぶ |
| ⌘ / Ctrl + Shift + クリック | 最深要素を複数選択に足す・外す |
| ⌘ / Ctrl + ドラッグ | 自由配置(スナップしない) |
| ⌘ / Ctrl + ダブルクリック | テキスト編集に入る |

押した瞬間にはどれになるか決められないので、選択の mousedown には手を入れず、移動はクリックが確定してから決める:

- mousedown(capture)で「押した点の下のリンク」を覚えるだけ。選択枠の上から押しても `elementsFromPoint` でその下のリンクを拾う
- 動かさずに離し(`MARQUEE_DRAG_THRESHOLD` 以内)、Shift / Alt を押しておらず、click の `detail` が 1 のときに 350ms 待つ
- 選択枠のハンドル(`[data-handle]`、リサイズ・回転)の上で押したときは、下にリンクがあっても候補にしない(ハンドルの操作)
- 待つ間に 2 回目の mousedown・dblclick・contextmenu・Escape が来たら取り消す。待った後も、押した点のリンクが同じで、
  テキスト編集に入っていないときだけ移る
- リンクの ⌘ + クリックでも、mousedown の最深要素の選択は今までどおり起きる(移った先では関係なく、アンカー・外部リンクではリンクが選ばれたまま)

これで:

- ⌘ + Shift + クリック: リンクでも移らず、複数選択に足す・外す(今までどおり)
- ⌘ + ドラッグ: 動かしたので移らない(自由配置のまま)
- ⌘ + ダブルクリック: 1 回目のクリックの移動は 2 回目の mousedown で取り消され、テキスト編集に入る
- リンクの中の深い要素を移らずに選びたいとき: **⌘ + Alt + クリック**(最深要素を選ぶ・移らない)。またはダブルクリックで潜る
- テキスト編集中: 編集中の要素の中の ⌘ + クリックでは移らない(文字を直している途中にページが変わらないように。
  キャレットが動くだけ)。編集中の要素の外のリンクなら、今までどおり mousedown で編集を抜け、保存してから移る

Mac は ⌘ だけ。Mac の Chromium は Ctrl + クリックを右クリックとして扱い(`contextmenu` を出し、`click` を送らない)、
エディタのコンテキストメニューが開く。案内とカーソルも Mac では ⌘ のときだけ。Windows などは Ctrl(と Meta)。

ダブルクリックの間隔が 350ms より長い人は、1 回目で移ってしまう(OS のダブルクリック間隔は JavaScript から読めない)。

### 分かっている穴

- キャンバスで編集中でないページ(見るだけの紙面)のリンクには効かない。そこを ⌘ + クリックすると、今までどおりそのページが編集中になるだけ
- リンクの ⌘ + クリックは、移る前に mousedown の最深要素の選択も起きる(アンカー・外部リンクのあとはリンクが選ばれたまま)
- 1 ページ表示では `handleContentChange` がページを読み込んだあと、利用側(構成ラフの殻)が `contentId` の変更で作り直すので、
  読み込みが 2 回走る(エディタの中のページ一覧で切り替えるときと同じ経路)
- 別ページのアンカーは、移り先の紙面の読み込みから 500ms 待って寄せる。読み込みがそれより遅れて高さが変わると、ずれることがある
- `target="_blank"` は見ない(サイト内のページならエディタの中で移る)
- 案内の吹き出しは親の文書に置いたインラインスタイルの黒地で、エディタの配色(ライト / ダーク)には合わせていない
- Windows は実機で確かめていない(`navigator.platform` を Win32 に見せかけ、Ctrl + クリックは合成イベントで確かめた)
