# 左のパネルを出し入れしても、キャンバスの紙面を動かさない(0.7.0)

依頼: 「左のサイドパネルを非表示から表示にすると、キャンバス自体がずれる。キャンバスは固定にしたい」。
Figma と同じく、パネルが出た分だけ見える範囲が狭くなるだけで、紙面(フレーム)は画面上の同じ位置に留める。

## 直す前(実測)

ヘッダーの「左パネルの表示を切り替え」で 非表示 → 表示 にすると、紙面が **右へ 264px**(左パネルの幅)動いた。
表示 → 非表示 では左へ 264px 戻る。倍率は変わらない。拡大・移動した後でも同じ量。

| 表示 | 最初の視点 | 拡大・移動の後 |
| --- | --- | --- |
| 構成ラフ キャンバス(マルチフレーム) | +264px | +264px |
| 構成ラフ 1 ページ | +264px | +264px |
| 提案書デッキ キャンバス | +264px | +264px |
| 提案書デッキ 1 枚(Figma 風の殻) | +264px | +264px |

- 提案書デッキの PowerPoint 風の殻には左パネルの出し入れが無い(サムネイルのレールは常に出ている)ので起きない
- 右のパネル(構成ラフで要素を選ぶとプロパティが出る / デッキでコメントを開くとプロパティと入れ替わる)では、紙面は動かなかった(0px)

## 原因

キャンバスの位置の基準が、キャンバスの容器(`FrontendVisualEditor` の `canvasAreaRef`、flex の行で左パネルの右に並ぶ)の **左端** だった。
左パネルが出ると容器の左端がパネルの幅だけ右へ動き、紙面も一緒に動く。右のパネルは容器の右端しか動かさないので、紙面は動かない。

- マルチフレーム(`MultiPageCanvasView`): 転写層の `translate(canvasOffset)` は容器の左上から
- 1 ページ表示(`EditorCanvas`): 容器いっぱいの iframe の中で、紙面は `#canvas-container` のスクロールで置かれ、その基準は iframe の左端

## 直し方

入口(ヘッダーのボタン、部品パネルが左パネルの代わりに出る、パネルの幅のドラッグ、利用側のレール)ごとには手当てせず、
**容器の左端の変化そのもの** を `ResizeObserver` で見て、動いた分だけ打ち消す。左端は幅と一緒にしか動かないので拾える。
呼ばれるのはレイアウトの後・描画の前なので、ずれた姿は描かれない。キーボードショートカットで左パネルを出し入れする経路は元から無い。

- マルチフレーム: `MultiPageCanvasView` が容器を見て、`shiftView(-dx, -dy)`(`MultiPageCanvasContext`)で位置を逆にずらす。
  `viewStore` は購読者(転写層の transform)へ同期で書く。全体表示などのアニメーションの途中でも止めず、行き先も同じだけずらす
- 1 ページ表示: `useKeepArtboardInPlace`(`EditorCanvas` が、マルチフレームでないときだけ使う)が容器を見て、
  `#canvas-container` を同じ向きへ `dx` だけスクロールする(`scrollCanvasLeftTo`、`utils/dom-utils.ts`)
  - 行き先がスクロールできる範囲の外(縮小した紙面でパネルを閉じると、左端より手前へ戻す必要がある)なら、
    `#canvas-scroll-area` を左右へ `e` ずつ広げて届かせる。紙面は中央寄せなので `e` だけ右へ動き、行き先にも `e` を足す。
    広げた幅は次に倍率が変わったとき `applyCanvasZoomDom` が測り直す(今までどおり中央へ寄る)
  - 容器が広がると、ブラウザはレイアウトの時点で(`ResizeObserver` より前に)スクロール位置を新しい上限へ詰める。
    詰められる前の位置は読めないので、スクロールのたびに覚えておく。覚えるのは iframe の表示幅が前回の `ResizeObserver` のときと同じ間だけ
    (幅が変わった後に届くスクロールは詰められた結果)
  - 縦は手当てしていない(左右のパネルは容器の高さを変えない)

### ついでに見つけたもの: 部品パネルを閉じると、キャンバスの紙面が縦にずれた(直す前から)

部品パネルを閉じると、エディタへフォーカスを戻す `iframe.focus()` で、ブラウザが要素を見せようとして
`overflow: hidden` の容器(`[data-infinite-canvas]`)そのものをスクロールする。位置は transform が持つので、
紙面がスクロールした分(縮小した構成ラフで上へ 61px)ずれたまま戻らない。直す前の版でも同じ量で起きる。
`MultiPageCanvasView` で、容器のスクロールが起きたら 0 へ戻す(フォーカスの経路を問わない)

## 確かめたこと

Playwright(headless Chromium、1440×900)で、`npm pack` した tgz を入れた構成ラフの殻・提案書デッキと、playground で確かめた
(`verify-panel-shift.mjs`)。紙面(`#artboard`)の画面上の左上が 1px 以内で変わらないこと、倍率が変わらないことを見る。

- 表示: 構成ラフのキャンバス / 1 ページ、提案書デッキのキャンバス / 1 枚(Figma 風)、playground のキャンバス / 1 ページ
- 非表示 → 表示 → 非表示(最初の視点、拡大・移動した後)
- 表示 → 非表示 → 表示(パネルを出したまま拡大・移動した後、紙面が容器より狭くなるまで縮小した後、1 ページ表示で右端までスクロールした後)
- パネルの幅をドラッグで 80px 広げて戻す
- 部品パネル(ツールバーの「パネル」→「コンポーネント」)を、左パネルが無いとき / 左パネルの代わりに出して閉じる
- 選んだ要素の選択枠が、切り替えの前後で要素に重なったまま。要素も画面上で動かない
- 右のパネルの出し入れで紙面が動くか(測るだけ)。どの表示でも 0px
- 部品パネルを閉じた後、キャンバスの容器のスクロールが 0 のまま(直す前の版は 61)
- 直す前の版では、上の表のとおり 264px ずれて落ちる
- 結果: `verify-panel-shift.mjs` 196 / 196。既存の回帰 `verify-canvas.mjs all` 44 / 44、`verify-single.mjs` 30 / 30、`verify-editor-fixes.mjs all` 93 / 93
  (1 回目は `verify-single` と `verify-editor-fixes` の br で「Failed to load CSS variables: TypeError: Failed to fetch」が 1 件ずつ出た。
  検証が localStorage を入れるために読み込みを打ち切ったときの fetch の中断で、その 2 つを回し直すと出なかった)

## 分かっている穴

- 依頼の文面は「左にずれる」だが、手元の構成ラフの殻・デッキ・playground で測ったのは右へ 264px。利用者の環境の姿は見ていない
- 容器の左端が **幅を変えずに** 動く場合(左のパネルが同じ幅の別のパネルに替わる、など)は `ResizeObserver` が呼ばれず、打ち消さない。今のエディタの入口には無い
- 1 ページ表示で、倍率を変えた同じフレームのうちにパネルを出し入れすると、覚えているスクロール位置が古いことがある(スクロールのイベントは次のフレームに届く)
- 保存しているキャンバスの位置(`canvasStorageKey`)は、ずらした後の位置になる。左パネルの表示は記憶しないので、
  パネルを出したまま閉じて開き直すと、紙面はパネルの幅だけ左に見える(直す前は同じ位置に見えていた)
- 実機のブラウザ(Safari・Firefox)、トラックパッドのピンチ中の出し入れは確かめていない
