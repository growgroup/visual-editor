# ⌘ / Ctrl + クリックでリンク先へ移る(0.7.0 の後)

紙面の中のリンク(`<a href>`、またはリンクの中の要素)を ⌘ + クリック(Windows などは Ctrl + クリック)すると、
リンク先へ移る。普通のクリックは今までどおり選択。

- 実装: `src/editor/utils/link-navigation.ts`(リンク先の解決と紙面のイベント)、
  `src/editor/hooks/useLinkNavigation.ts`(エディタ側の行き先)、`EditorCanvas` が紙面の読み込みごとに付ける

## 行き先

| リンク | 動き |
|---|---|
| 同じサイトのページ(`contentList[].href` と一致) | キャンバス: `focusPage` で視点を寄せ、`activatePage` で編集中にする。1 ページ表示: `onContentChange`(= `handleContentChange`)。どちらも未保存の変更を保存してから移る |
| 同じページのアンカー `#id` | その要素が見える位置へ紙面を移す。`#` だけ・`#top`(同じ id が無いとき)は先頭 |
| 別ページのアンカー `/company#access` | そのページへ移り、読み込みが落ち着いたら(500ms)その要素へ寄せる |
| 別のオリジンの http(s) | 新しいタブ(`noopener,noreferrer`)。紙面の iframe は sandbox に `allow-popups` が無いので、親のウィンドウで開く |
| `mailto:` / `tel:` / `javascript:` など | 何もしない |
| 同じオリジンで一覧に無い | 「このリンク先はページ一覧にありません」を押した所の近くに 2.4 秒出す |

ページの照らし合わせ:

- `/company`・`/company/`・`/company/index.html` は同じ。`?query` は見ない。`#hash` は上のとおりアンカーに使う
- 相対パスはページの URL を基準に解く。`/company` の中身は `company/index.html` なので、基準は `/company/`
  (`./access` → `/company/access`、`../` → `/`)。`/about.html` のように拡張子のある URL はそのまま基準
- 完全に一致するページが無いときだけ、`/about` と `/about.html` を同じと見なす
- `contentList[].href` が絶対 URL(本番のドメインなど)なら、そのオリジンのリンクも一致する
- 提案書デッキのように `href` を渡していない一覧では、サイト内のリンクは「ページ一覧にありません」。外部とアンカーは効く

## ⌘ を押している間

リンクの上ではカーソルが指になり、カーソルの右下に行き先が出る(`⌘ クリックで移動: 02 サービス` /
`⌘ クリックで新しいタブ: example.com` / 一覧に無いときは `このリンク先はページ一覧にありません` で、カーソルは変えない)。
`mailto:` などとリンク以外では出さない。紙面の外へ出る(`mouseleave` / `relatedTarget` の無い `mouseout`)・ウィンドウが
フォーカスを失う・⌘ を離すと消す。案内は親の文書に置く(キャンバスの外側の倍率で文字が縮まないように)。
カーソルは紙面の `<html data-gg-link-nav>` と `EDITOR_IFRAME_STYLES` の `cursor: pointer !important`
(選択枠などのオーバーレイの上でも指になる)。

## 既存の ⌘ / Ctrl クリックとの両立

既存の意味(`useElementSelection` / `useDragResize`):

| 操作 | 意味 |
|---|---|
| ⌘ / Ctrl + クリック | 階層を無視して最深要素を選ぶ |
| ⌘ / Ctrl + Shift + クリック | 最深要素を複数選択に足す・外す |
| ⌘ / Ctrl + ドラッグ | 自由配置(スナップしない) |
| ⌘ / Ctrl + ダブルクリック | テキスト編集に入る |

押した瞬間にはどれになるか決められないので、選択の mousedown には手を入れず、移動はクリックが確定してから決める:

- mousedown(capture)で「押した点の下のリンク」を覚えるだけ。選択枠の上から押しても `elementsFromPoint` でその下のリンクを拾う
- 動かさずに離し(`MARQUEE_DRAG_THRESHOLD` 以内)、Shift / Alt を押しておらず、click の `detail` が 1 のときに 350ms 待つ
- 選択枠のハンドル(`[data-handle]`、リサイズ・回転)の上で押したときは、下にリンクがあっても候補にしない(ハンドルの操作)
- 待つ間に 2 回目の mousedown・dblclick・contextmenu・Escape が来たら取り消す。待った後も、押した点のリンクが同じで、
  テキスト編集に入っていないときだけ移る
- リンクの ⌘ + クリックでも、mousedown の最深要素の選択は今までどおり起きる(移った先では関係なく、アンカー・外部リンクではリンクが選ばれたまま)

これで:

- ⌘ + Shift + クリック: リンクでも移らず、複数選択に足す・外す(今までどおり)
- ⌘ + ドラッグ: 動かしたので移らない(自由配置のまま)
- ⌘ + ダブルクリック: 1 回目のクリックの移動は 2 回目の mousedown で取り消され、テキスト編集に入る
- リンクの中の深い要素を移らずに選びたいとき: **⌘ + Alt + クリック**(最深要素を選ぶ・移らない)。またはダブルクリックで潜る
- テキスト編集中: 編集中の要素の中の ⌘ + クリックでは移らない(文字を直している途中にページが変わらないように。
  キャレットが動くだけ)。編集中の要素の外のリンクなら、今までどおり mousedown で編集を抜け、保存してから移る

Mac は ⌘ だけ。Mac の Chromium は Ctrl + クリックを右クリックとして扱い(`contextmenu` を出し、`click` を送らない)、
エディタのコンテキストメニューが開く。案内とカーソルも Mac では ⌘ のときだけ。Windows などは Ctrl(と Meta)。

ダブルクリックの間隔が 350ms より長い人は、1 回目で移ってしまう(OS のダブルクリック間隔は JavaScript から読めない)。

## 確かめたこと

Playwright(headless Chromium)。構成ラフの殻・提案書デッキの殻の複製に、このブランチの tgz を入れて確かめた。

- リンク先の解決(`resolveLinkTarget`)の単体: 27 / 27。`/company`・`/company/`・`/company/index.html`・`./company`・`company`・
  `../`(2 階層)・`?x=1`・`#hash`・同じオリジンの絶対 URL・`//host/…`・`/about` ↔ `/about.html`・日本語のパス・本番ドメインの `href`・
  `#` / `#top` / 空・外部・`mailto:` / `tel:` / `javascript:`・一覧に無いパス
- 画面の検証: 57 / 57(キャンバス 31・1 ページ表示 15・Windows の見かけ 5・デッキ 4・後始末 2)。
  そのあとハンドルの検証を「リンクに重なるハンドル」を探して押すように直し、キャンバスを回し直して 33 / 33
  - キャンバス: ⌘ + クリックでページ 2〜7 へ(`/services/`・`/case-studies/index.html`・`./news`・`news/detail?from=top`・`/faq#q1`・`../contact`)。
    移り先が編集中になり、フレームが画面に入り、殻の URL(`?path=`)が追う。`/services#flow` は移ったあと `#flow` が画面に入る
  - 1 ページ表示: `/services/`・`../contact` で切り替わる。移り先のページファイルは書き換わらない
  - 同じページのアンカー(キャンバス・1 ページ表示): 画面の外にあった要素が画面に入る
  - 外部リンクで新しいタブ(`popup` イベント)。`mailto:` / `tel:` では何も起きない。一覧に無いリンクは知らせて移らない
  - 普通のクリックは選択。⌘ + ダブルクリックでテキスト編集に入り移らない。編集中のリンクの中の ⌘ + クリックでは移らない
  - ⌘ + Shift(複数選択に足す)・⌘ + Alt(最深要素)・⌘ + ドラッグ・選択枠のハンドルの上の ⌘ + クリックでは移らない。Mac の Ctrl + クリックはメニューが開き移らない
  - 未保存の変更: テキストを打って自動保存(2 秒)の前に、編集を抜けずに別のリンクを ⌘ + クリック → 移る前にページファイルへ書かれている
  - ⌘ を押している間の案内と指のカーソル(カーソルを `default` にしたリンクでも指になる)、離すと消える。リンク以外・`mailto:` では出ない
  - Windows の見かけ(`navigator.platform` = Win32): 「Ctrl + クリックで移動」の案内、Ctrl + ダブルクリックでテキスト編集、Ctrl + クリックで移る(1 ページ表示・キャンバス)
  - デッキ(キャンバス): スライド内の外部リンクで新しいタブ、サイト内リンクは「ページ一覧にありません」
- 既存の操作の結果を、変更前のパッケージ(同じ tgz から今回の変更だけを戻したもの)と並べて比べた: 1 ページ表示とキャンバスで 16 項目ずつ、32 / 32 同じ
  (素のクリック・⌘ クリック・⌘ + Shift の追加と解除・リンクの ⌘ クリック直後の選択・⌘ + Alt・ダブルクリックで潜る・⌘ + ダブルクリック・Ctrl クリック・⌘ + ドラッグの移動量)
- 既存の回帰: verify-single 15 / 15、verify-comments 40 / 40、verify-canvas 16 / 20、verify-editor-fixes 68 / 71
  - verify-canvas の deck-switch 3 件と deck-pin 1 件は、変更前のパッケージを入れたデッキの複製でも同じように落ちた(複製した殻の環境。パッケージの src は fixes の tgz と同じ)
  - verify-editor-fixes の minmax(スライド)2 件とリボンの例外 1 件は、単独で回し直すと 31 / 31(変更前のパッケージでも 31 / 31)。回帰を続けて回した後のデッキの殻の状態によるもの

## 分かっている穴

- キャンバスで編集中でないページ(見るだけの紙面)のリンクには効かない。そこを ⌘ + クリックすると、今までどおりそのページが編集中になるだけ
- リンクの ⌘ + クリックは、移る前に mousedown の最深要素の選択も起きる(アンカー・外部リンクのあとはリンクが選ばれたまま)
- 1 ページ表示では `handleContentChange` がページを読み込んだあと、利用側(構成ラフの殻)が `contentId` の変更で作り直すので、
  読み込みが 2 回走る(エディタの中のページ一覧で切り替えるときと同じ経路)
- 別ページのアンカーは、移り先の紙面の読み込みから 500ms 待って寄せる。読み込みがそれより遅れて高さが変わると、ずれることがある
- `target="_blank"` は見ない(サイト内のページならエディタの中で移る)
- 案内の吹き出しは親の文書に置いたインラインスタイルの黒地で、エディタの配色(ライト / ダーク)には合わせていない
- Windows は実機で確かめていない(`navigator.platform` を Win32 に見せかけ、Ctrl + クリックは合成イベントで確かめた)
